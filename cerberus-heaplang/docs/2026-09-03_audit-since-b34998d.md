## Executive verdict

The logical content of the range is sound and, at the theorem level,
honest: the shipped round `CerberusRound` is genuinely one iteration of
the driver's thread loop with no hand-written definition in its
referent; `frag_round_complete` is exhaustive by construction over the
18 redex roots; every `ShippedRefusal` arm is an engine fact and none
is vacuous; the narrowing premises are discharged by `rfl` at every
exhibit and no rule, exhibit or production statement changed (verified
against the signature snapshots); the guard repair does what it says.

Two things a careful reader would object to:

1. **Medium — the residual is described as engine successes and is not.**
   `OpenRound.eval_uncovered` is documented on every surface (its own
   docstring, README register row, ARCHITECTURE §2/§7, WALKTHROUGH §5/§7,
   DECISIONS "FRAGMENT CLOSURE LANDED") as "an operand in the covered
   grammar that the engine ACCEPTS where the mirror does not evaluate"
   / "that the engine's evaluator does NOT reject", and correspondingly
   "every rejected operand is now a proved engine KILL". The theorem
   proves neither: `.uncovered` carries no engine claim, and the
   classifier answers `.uncovered` for any compound operand whose first
   uncovered LEAF is accepted — after which the engine may KILL. I
   exhibited one by execution (below): `f + 1` with `f` a `Proc`-named
   unbound symbol is `PePure`, the classifier says `uncovered`, the
   engine says `Exception (Illformed_program … ill-typed PEop …)`. So a
   class of engine KILLs the docs say is classified sits inside the
   residual, and the residual is not "exactly" the accepted-but-
   unmirrored operands. Soundness of the disjunction is unaffected (the
   residual is honest as stated in Lean); the shop-window claim is not.

2. **Note (structural) — nothing in the adequacy chain consumes the
   round.** `CerberusRound`, `engine_step_matchU`, `step_iff_cerberusRound`,
   `cerberusRound_classify`, `frag_round_complete` are certificates that
   stand beside the two lanes: the partial lane consumes
   `outcomesU_of_step` (the device, over `dischargeStep`) and the total
   lane consumes `loop_step_frag`, which is proved independently of
   `CerberusRound` by its own ~500-line case analysis. The docs' "is
   this theorem's instance at the production profile" is a semantic
   remark, not a derivation. Not a hole; a duplication and a reading
   hazard (several module headers still say `engine_step_matchU`
   discharges each drive step).

Merge recommendation: **merge after the documentation fix for finding
M-1** (a wording change on five surfaces plus one DECISIONS erratum; no
Lean change required). Everything else is Note-level.

## Findings

### M-1 (Medium). The residual `eval_uncovered` is documented as engine successes; it also contains engine kills (and panics), so the KILL-coverage claim is overstated

Location: `Round.lean` `OpenRound.eval_uncovered` docstring; README
"Registered divergences" row and §"Where the headline claim rests"
paragraph 3; ARCHITECTURE §2 and §7; WALKTHROUGH §5 and §7;
`docs/DECISIONS.md` "2026-09-02/03 [AGENT] FRAGMENT CLOSURE LANDED".

Claim (verbatim, the arm's docstring): "An operand of the
configuration's redex, in the covered grammar, that the mirror
evaluator does not evaluate and that the engine's evaluator does NOT
reject: `evalClass … = .uncovered` … Every OTHER mirror-stuck operand
is a classified KILL". README: "`eval_uncovered` — an operand in the
covered grammar that the engine ACCEPTS where the mirror evaluator does
not evaluate". ARCHITECTURE §2: "a configuration the mirror refuses is
one the engine refuses too, in the engine's own vocabulary, except at
the residual's two shapes (an operand the engine ACCEPTS where the
mirror evaluator does not evaluate …)". DECISIONS: "every rejected
operand is now a proved engine KILL (`Other (DErr_core_run …)`, exact
payload) through the new `EvalClass` kill bridge".

Tree's truth. `evalClass` (EvalClass.lean:104) at `PEop`:

```lean
  | Pexpr _ _ (PEop op pe1 pe2) =>
      match evalClass tds loc ext file ρ pe1 with
      | .kill err => .kill err
      | .uncovered => .uncovered
      | .val v1 => …
```

so the FIRST uncovered leaf decides `.uncovered` for the whole operand,
whatever the engine then does with the accepted leaf's value. The
engine (`step_eval_peop`, Core_eval.lean) evaluates both children and
dispatches on the value pair; a null function pointer (the `Proc`
arm's value) against an integer falls to the ill-typed-PEop
`Illformed_program` exception. Executed (above): `isPePure pe0 = true`,
`evalClass … pe0 = .uncovered`, engine `Exception (Illformed_program …)`
— a KILL via `liftCore_run` in the shipped driver, not an acceptance.
The same holds for a float leaf under `Eif` (the engine's non-boolean
`failwithI` panic), and for `OpEq` at two ctypes used as an integer
operand. The EvalClass module header alone is honest about this:
"`EvalOut.uncovered` — the engine SUCCEEDS with a value the mirror does
not compute, **or the outcome is not characterized here**"; the arm's
docstring and every shop-window surface drop the second clause.

Consequence. The disjunction `frag_round_complete` remains true (the
arm makes no engine claim beyond the step's shape), but (i) the
residual is NOT "exactly the configurations with an accepted-but-
unmirrored operand" ([WORKER], closure notes) — it is the configurations
with an accepted-but-unmirrored LEAF somewhere in an operand, the
whole operand's fate uncharacterized; (ii) "every rejected operand is a
proved engine KILL" is false for rejections downstream of such a leaf;
(iii) ARCHITECTURE's "a configuration the mirror refuses is one the
engine refuses too … except at the residual" reads as if the residual
were the engine's successes, and a reader would infer the KILL
classification is total on `PePure`. Under the brief this is a
statement not saying what the docs say it says; I grade it Medium
because the Lean statement is honest and the overclaim is in the
prose; the operator may grade it High if the residual's
characterization is read as part of acceptance goal (2).

Fix (a statement). Replace, on all five surfaces and in the DECISIONS
entry, "an operand the engine ACCEPTS where the mirror does not
evaluate" by: "an operand containing a LEAF the engine accepts where the
mirror evaluator does not evaluate (a `Proc`-named unbound symbol, a
mirrored binop at two floats, `OpEq` at two ctypes); the engine's
outcome on the WHOLE operand is not characterized — it may succeed,
kill on a later type error, or panic (Eif at a non-boolean)"; and
replace "every rejected operand is a proved engine KILL" by "every
operand the classifier rejects (`evalClass … = .kill err`) is a proved
engine KILL; a rejection downstream of an uncovered leaf is in the
residual". Alternatively (the registered mover, which also empties the
residual's success cases into `Step`): make `evalClass` compute the
engine's value at the three uncovered leaf shapes (`nullPtrval (Ctype
[] Void0)`, `opFval`/`eqFval`/`ltFval`/`leFval`, `ctypeEqual`) so that
`.uncovered` is reserved for the leaf itself and the KILL bridge covers
the downstream rejections.

## The questions, answered

**1. The shipped round.** `CerberusRound` (Round.lean:165) is exactly
the loop body's shape. The generated loop (Driver.lean:348) is
`nd_bind (nd_read (fun dr_st => let th_info := match lookupBy (==) tid1
dr_st.core_state0.thread_states with | some z => z | none => failwithI …;
step_ctx tds dr_st.layout_state dr_st.core_file dr_st.core_extern tid1
th_info)) (fun steps => match find_can_advance steps with | none => …
| some step1 => nd_bind (advance_step tds tid1 step1) (fun wakeups => …
NOWAKEUP => tid1 :: xs' …))`; `find_can_advance [s] = some s ↔
can_advance s = true`; the round's three conjuncts are these three
parts, and `loop_step_of_advance` (Round.lean:400) assembles them into
`runOne (aux2 (fl+1) tds acc [tid]) dst = runOne (aux2 fl tds acc [tid])
dst'` for every `fl`/`acc` by `conv => lhs; unfold` — no fuel-zero arm
is evaluated, so "no fuel dependency" is correct. `runOne` is `match m
with | ND f => f s` (DriverCollapse.lean:98) — the `ND` eliminator, no
content. `MachineCtx.Embeds` is complete for the round's OUTCOME: on the
fragment's four step kinds `advance_step` reads only `core_run_state0`
(`liftCore_run`, `fresh_action_id'`), `layout_state` (`liftMem`),
`core_state0` (`update_thread_state`, which preserves every other
`core_state` field via `{st with thread_states := …}`), and WRITES
`trace`/`dr_step_counter` (existentially quantified in the round);
`concurrency_state` is read only in the `Step_thread_done2` arm,
`blocked`/`fs_state0`/`symbolic_assoc` nowhere on this path;
`perform_action_request2` at `with_concurrency = false` draws the aid
and calls `action_request_sequential2`. `CerberusRound.runND` gives the
runner-level singleton via `runND_active`. The total-lane collapse does
NOT go through the restated round (N-1): `loop_step_frag` is
independent, `prod_run_eqJ` consumes it. Exports still stated over the
device: every PROVISIONAL `driveU` export (`engine_adequacyU`,
`wpt_engine_boundU*`, `MemTripleU*`, the projections) — labelled as
such; none of the Round exports mention `dischargeStep`/`outcomesU`.

**2. Completeness.** Dispatch is `Frag.decomp` → `Decomp e ctx r ∧ Frag
r` → `cases hd.redex` over the 18 `Redex` constructors (store, load,

`ShippedRefusal` arm is an ENGINE fact quantified over all embedding

_)`; `fork` is `2 ≤ (CerbND.runND (advance_step …)).length`, proved by
