## 1. Required fix 1 — `peDepth` / `PePure` named in the front documents

**Finding (Q2, §3.1).** `Frag.if_/run/save/load_op/memop_op/store_op`
carry `peDepth pe ≤ lemDefaultFuel` (and the three operand-evaluation
constructors `PePure pe`); neither README nor WALKTHROUGH mentioned
`peDepth`.

**Verified in the tree.** `PePure` (Soundness.lean: `val`, `sym`, `op`
at any `binop`, `arrayShift`), `peDepth` (`1` at a leaf, `1 + max` at
`PEop`/`PEarray_shift`), `peDepth_sym_le`/`peDepth_val_le` (`rfl`-grade
at `lemDefaultFuel = 999999 + 1`), `evalPexpr_shape` (evaluator success
implies `PePure`), and the constructor premises quoted below. The
engine side: `step_eval_pexpr`/`pull_constrained` are fuelled at
`lemDefaultFuel` (the pure-evaluator bridge section of Soundness.lean).

**Where it now stands.** README "Scope, exactly", one paragraph
("Pure operands carry their own static fuel bound"); WALKTHROUGH §5,
one paragraph ("The second fuel bound: pure operands") with two
verbatim blocks; WALKTHROUGH §1.1 gains a pointer; the Soundness.lean
`Frag` section header gains "THE SECOND FUEL BOUND"; the Soundness
module header's FUEL HONESTY paragraph names it. The README sentence,
verbatim:

> **Pure operands carry their own static fuel bound.** The engine's
> pure-expression evaluator is fuelled at the same budget as its redex
> search (`step_eval_pexpr`/`pull_constrained` draw from
> `lemDefaultFuel`), so every `Frag` constructor that evaluates a pure
> operand — `if_` (the guard), `run` (the jump arguments), `save` (the
> initializers), `load_op`/`memop_op`/`store_op` (the operands the engine
> evaluates before dispatching the action) — carries the static premise
> `peDepth pe ≤ lemDefaultFuel` per operand, where `peDepth`
> (Soundness.lean) is the operand's syntactic depth (1 at a value or a
> symbol, `1 + max` at `PEop`/`PEarray_shift`); the three
> operand-evaluation constructors also restrict their operands to the
> sub-grammar `PePure` the mirror evaluator covers (values, symbols,
> `PEop` binops, `PEarray_shift`), while for `if_`/`run`/`save` the grammar
> is enforced by the rule's `evalPexpr … = some …` premise
> (`evalPexpr_shape`: success implies membership). Verbatim, the premises
> of `Frag.store_op`: `(hp2 : PePure pe2) (hp3 : PePure pe3) (hd2 : peDepth
> pe2 ≤ lemDefaultFuel) (hd3 : peDepth pe3 ≤ lemDefaultFuel)`. Like the
> `pot` bounds below, this bound is `rfl` for every authored program
> (`peDepth_sym_le`, `peDepth_val_le`) and never mentions the run length;
> unlike them it lives inside `Frag`, so it appears on no exhibit as a
> separate hypothesis.

The WALKTHROUGH's two blocks quote `Frag.if_` in full and `Frag.store_op`
from its `hnv` premise to its conclusion (the block starts below the
`{loc …}` binder line so that commit B's removal of `hlib` left it

`PePure` is a premise only of `load_op`/`memop_op`/`store_op`; for

success premise — the documents say so rather than claiming a `PePure`

their location argument only in `let fail_ (err : mem_error) :=
(NDkilled (failReason err loc), st)` (CerbMem.lean:1623, :1669);
`allocateObject` takes none. So:

1. `requestLoc (th : thread_state) (loc) := if isLibraryLocation loc then
   th.current_loc else loc` (Soundness.lean) names the engine's
   conditional.
2. `storeM_loc_irrel`/`loadM_loc_irrel` (Step.lean, next to `applyMemM`):
   `applyMemM (storeM tds loc' ty lk pv mv) σ = applyMemM (storeM tds loc

   the memory operation, rewrite `applyMemM (ND f) σ` to the one-layer

   the pointer, then `repeat' (first | rfl | split)` — every `fail_` arm
