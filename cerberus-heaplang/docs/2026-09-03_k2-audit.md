### Q4. The rule

Precondition: `pointsToCell tds pv (.own 1) ty bs` = `∃ id a, ⌜pv = cellPtr
id a⌝ ∗ cellOwn tds id (.own 1) ⟨a, ty, bs⟩`, and `cellOwn` = `metaOwn i dq
(metaOf tds c) ∗ bytesOwn c.addr dq c.bytes ∗ ⌜length ∧ decIndep⌝`
(Heap.lean:2380-2399) — the whole-cell bundle: the metadata cell at
`.own 1` (`objCell tds a ty true false`, so alive, writable, `dynamic :=
false`) and every byte of the allocation at `.own 1`. No `_at`/view kill
rule exists (grep: the only kill rules are `kill_atomic`, `wps_kill`,
`wps_kill_emp`, `wps_kill_eval`, `wpt_kill`, `wpt_kill_emp`,
`wpt_kill_eval`; the base `9f0c20b` had none). A view (`pointsToView … dqm`
with `dqm < 1`) cannot satisfy it: `metaHeap_update` needs `metaOwn id
(.own 1)`. Right precondition: the engine kills the whole allocation, and
full metadata ownership is what makes `emp` sound (no other fraction can
assert liveness afterwards; `allocMeta` at `.discard` forecloses the kill —
`deadObj_allocMeta_false`).

Soundness of the ghost step. `kill_atomic` (Rules.lean) destructs the
points-to as `⟨%i, %addr, %Hpv, Hm, -, -⟩` (bytes and layout facts
dropped), reads `get? mm i = some (objCell … true false)` from
`metaHeap_valid`, runs the real engine through `killM_success σ₁ i _ loc
(HG.metas i _ Hgetm) rfl` (after `rw [hstatic]`), inverts the step with
`Step.kill_inv` (unique successor), then `metaHeap_update (objCell tds addr
ty false false)` and `metaOwn_persist`, and re-establishes the state
interpretation with `CohG.kill`. `CohG.kill`'s statement (printed):
`CohG σ mm mb mk → get? mm id = some mc → mc.alive = true → CohG { σ with
deadAllocations := id :: …, allocations := σ.allocations.erase id }
(insert mm id { mc with alive := false }) mb mk` — the byte heap `mb` and
cursor heap `mk` are the SAME. Why this is sound with the byte fragments
dropped: (i) `killM`'s active arm writes only `deadAllocations` and
`allocations` (:1576-1578) — `σ.bytemap` is untouched, so `CohG.bytes : get?
mb k = some b → byteAt σ k = b` transfers verbatim; (ii) addresses are
never reused: `allocateObject` (CerbMem.lean:1511-1522) sets `addrAfterSize
:= st.lastAddress - size` with `size := (sizeofCtype …).max 1`, `alignedAddr
:= alignDown addrAfterSize.toNat align`, `lastAddress := alignedAddr` — the
cursor strictly descends and every new object lies below it;
`allocateRegion` (:1539-1546) the same with `size := sizeN.toNat` (may be
0, so non-strict — K3's concern; a zero-size cell is `metaDisjoint` from
anything). The dead cell keeps `addr`/`size` in `mm`, so `metas_disj`
(all tracked cells, dead included) and `cur_meta_lo` (dead cells at or
above the cursor) transfer, and `cur_byte_lo` keeps every stale ghost byte
key at or above the cursor. Hence a later `create` (`CohG.create`, which
mints keys strictly below the cursor) can never land inside the dead
range, and no live cell can overlap it (live cells are tracked, and
`metas_disj` separates them from the dead cell) — so no store ever writes
a dead address and the stale ghost bytes stay coupled forever. The dropped
fragments are simply unrecoverable (the `.own 1` for those keys is gone
from every context), which is what `emp` after dispose means.

`MemWF.killM` is proved for BOTH arms (diff: `cases prov <;> cases base <;>
… repeat' split at hrun`, the `free(NULL)` arm by `h.of_fields rfl rfl rfl
rfl rfl`, the concrete arm by `h.kill`); `#print axioms` for `MemWF.kill`,
`MemWF.killM`, `CohG.kill`, `kill_atomic`: `[propext, Classical.choice,
Quot.sound]`; `sorryAx` absent from every closure I traced.

Budget: `AtomicStep … 1 …` and `wpt_of_atomic`'s `hk : c + 1 ≤ k` give `2 ≤
k`; `wpt_create` is `2 ≤ k` (bare pointer value), `wpt_store`/`wpt_load`
are `3 ≤ k` (they deliver `.annot` values, `deliveryCost = 2`). The kill
delivers `.pure Vunit` (`deliveryCost = 1`), so `2 ≤ k` is the total
judgment's own accounting — matches. `wpt_kill_eval` at `k + 1 ⊢ k` matches
`wpt_load_eval`.
