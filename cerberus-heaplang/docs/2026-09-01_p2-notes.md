## The P2 pointer-flow design record (binds all three slices)

THE FORCING FACT (recorded before any conversion): the public create
rules quantify the fresh pointer universally in the continuation
(`∀ p, p ↦cell … -∗ Ψ(ptr p)` — the charter P1.4 shape). An
entailment `allocCap reqs ⊢ wps/wpt (…create; suffix(π)…)` where the
program TEXT hard-codes a concrete pointer π is FALSE in general:
`allocCap reqs` is satisfiable at other launch cursors, where the
engine mints p ≠ π and the suffix would access unowned memory. So
the pre-P2 allocating programs (create result DISCARDED by a
wildcard `lets _`, suffix authored against the allocator's concrete
output) are not verifiable through the public rule — by design, not
by accident: their shape was an artifact of the operational era.
CONSEQUENCE [AGENT 2026-09-01]: the P2 conversions re-author each
allocating program so the created pointer flows through the
PROGRAM's own binders (`Esseq (symPat p …) create …` — the mirrored
LETS-PURE at the sym binder — with heap access through the evaluated
operands `PEsym p` / `array_shift(PEsym p, …)`), which is also the
shape real Cerberus-generated Core has for `p = malloc(); …*p…`.
Statement consequence (the charter's sanctioned class, itemized per
slice): concrete cold-start addresses/allocation ids move OUT of the
program texts and conclusions and INTO the boundary evaluation of
the concrete plans (the PlanFits arithmetic at the cold-start
cursor); converted conclusions bind the allocation id/address
existentially — the logic binds the pointer, the engine picks it.

THE BOUNDS EXPORT (needed by slice 3's list build, landed in slice 1
so the rule statements move once): `isList`'s node-WF facts demand
`0 < a < 2^64` for every node address, and the generic list logic is
never parameterized or weakened (the charter's demand). The public
create rules therefore export the fresh pointer's pure
machine-address bounds `⌜0 < addrOf p ∧ addrOf p < 2^64⌝` in the
continuation — the charter P1.4 allowance ("the postcondition may
also provide … bounds knowledge"; the pure form pending P4's
metadata split). Provenance of the bound: `allocCap`'s hidden cursor
now carries `c.lastAddr ≤ 2^64` (`LaunchCoh.la_wf` at launch — real
Cerberus starts the downward cursor at 0xFFFFFFFFFFFF < 2^64 — and
`freshBase_lt_two64`/`freshBase_add_le` preserve it across creates:
the downward allocator never mints above its cursor).
