## The P1.1 design record (lands with the first slice, operator-visible)

**Policy chosen: the abstract finite allocation-capacity resource**
(the charter's recommended minimal policy, adopted as recommended by
the arc plan's house wrapper — [USER 2026-09-01] via the charter
adoption). It certifies that a known finite sequence of create
requests will not hit Cerberus's allocation-refusal path ("out of
memory" kill, CerbMem.lean:1479). This is faithful to the concrete
deterministic downward-cursor allocator while hiding the cursor from
clients.

**Explicitly rejected** (charter P1.1): modeling an allocation-
failure result/state. Cerberus's driver classifies a failed
`allocateObject` as a refused/killed driver outcome, not RefinedC's
deliberate `AllocFailed` divergence; inventing RefinedC behavior and
calling it Cerberus soundness is the named anti-pattern. A failure
model is admissible only after proving its correspondence to an
actual Cerberus relational outcome — out of this arc's scope.

**The shape** (names per the charter, spellings unchanged):

- `AllocReq` (Heap.lean): `align : Int`, `ty : ctype` — exactly the
  client-visible read-set of one `create`. The type-specific
  non-atomic and decode-inert premises stay on the logical create
  rules, per the charter.
- `advanceCursor : AllocCursor → AllocReq → Option AllocCursor`
  (Heap.lean): the pure image of one successful `allocateObject` on
  the two cursor fields. MIRROR-CITE (the charter's reuse demand):
  its guard is EXACTLY `allocateObject_success`'s premise pair —
  `0 < sizeofCtype ty` (pins the engine's `max 1` padding away,
  CerbMem.lean:1475) and `freshBase la align (sizeof ty) ≠ 0` (the
  `alignedAddr == 0` out-of-memory kill arm, CerbMem.lean:1479) —
  and its update is EXACTLY that theorem's state update
  (`lastAddress := freshBase …`, `nextAllocId := nid + 1`,
  CerbMem.lean:1475-1490). `advanceCursor_some_inv` re-exports the
  guards, which is how the create rules will discharge
  `allocateObject_success` from a plan.
- `PlanFits : AllocCursor → List AllocReq → Prop` (Heap.lean): runs
  the requests IN ORDER (charter demand; order is semantically
  binding — see the unit test below).
- `allocCap (reqs : List AllocReq) : IProp GF` (Heap.lean): the
  opaque capacity assertion. Implementation (visible to the heap
  module and the create-rule internals only): existential ownership
  of the cursor fragment + a pure `PlanFits` proof. Clients get
  `allocCap_intro` (launch side), `allocCap_weaken` (prefix
  weakening: stop early, never reorder/skip), and — P1.4 — the
  public create rules. Client statements never name `AllocCursor`,
  `lastAddress`, `nextAllocId`, `freshBase`, `cursorOwn` (the grep
  test runs at the P1.4 slice).

## Slice 1 (merge row 2) — the allocation model

Landed (Heap.lean only; NO example constants — the merge-row

  (`advanceCursor_pos`, `advanceCursor_some_inv`,
  `advanceCursor_mk`, `PlanFits_nil`, `PlanFits_cons_iff`,
  `PlanFits.prefix`).
- `allocCap`, `allocCap_intro`, `allocCap_weaken`.
- The charter's pure success/failure unit proofs, generic over ANY
  4-byte object type (`sizeofCtype ty = 4` hypothesis — no example
  constants; the exhibits may instantiate at `intTy` later):
  - `planFits_order_sensitive`: `[align 16, align 1]` fits cursor 21
    (bases 16 then 12) while the SWAPPED plan does not (align-1 base
    17, then `alignDown 13 16 = 0` — the OOM arm). Swapping requests
    is not silently allowed when alignment changes the concrete
    cursor evolution: the charter's order test, as a committed
    theorem (both directions).

    (underflow to base 0). The insufficient-plan arm of "an empty or

    the empty-plan arm is structural (the public rule consumes
    `req :: rest` — no rule form exists at `[]`) and is recorded as
    a plant transcript at the P1.4 slice.

  the internal soundness proof" is run at the P1.4 slice, where the
