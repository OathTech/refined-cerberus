## 2. The two live-state designs ([AGENT])

**(A) `current_loc` on the control.** `Ctl` = `⟨κ, proc, execLoc, curLoc, sup⟩`;
`Ctl.upd a := { c with curLoc := locUpd a c.curLoc }` with
`locUpd a l := match get_loc a with | none => l | some loc => if isLibraryLocation loc then l else loc`
— verbatim the general arm's `let th_st := match maybe_loc …`. Every
general-arm `Step` rule's successor control is `ctl.upd a` at the REDEX
node's list `a`; the value arms (`ret`, `ret_annot`, PROGRAM-DONE) leave
the control's location. The driver tie: `ctlThread th₀ e ρ ctl` sets
`current_loc := ctl.curLoc`; `loop_step_frag'`/`loop_step_frag` take
`hcl : th₀.current_loc = ctl.curLoc` and deliver the successor thread
with `current_loc := ctl'.curLoc`; `DriverDoneAt p Q th₀ e ρ lc σ ψ k`
gains the location argument (`lc`), `DriverDoneCtl`/`DriverSafeCtl`
gain the final location and supplies as existentials (`lcfin spfin`).
The adequacy exports lose their `hcl : th₀.current_loc = M.currentLoc`
premise (`engine_adequacy(_alloc)`, `SemTriple`, `MemTriple(_alloc)`);
`MachineCtx.currentLoc` is DELETED. The production entry: `prodCtl`
carries the parked thread's `CerbLocation.other "Driver.drive"`
(Driver.lean:530) and is `@[reducible]` (the readouts unify against it
by eta); `prod_run_eqJ` takes `DriverDoneAt … (other "Driver.drive") …`.
Where the evaluation is classified (`evalClass_of_none`, the `*_kill`
equations) the location is the ORIGINAL thread's (`th.current_loc` =
`ctl.curLoc`), because the engine evaluates operands before the
rebinding takes effect — an early generalisation to the updated
location was WRONG and was reverted (the engine equation would not have
matched).

Reasoning: the design measurement's option (C) (design-2 §4.3;
E0 §B.8) — the location is per-thread mutable state read by the PCALL
push, the action/memop requests and the evaluator's undef payloads, so
it is control state exactly like `execLoc`, which already lived on
`Ctl`; making it a `Ctl` field keeps `Config = CoreExpr × EnvStack × Ctl × Mem`
and lets `Ctl.callPush a ctx f` push `push_exec_loc f (locUpd a c.curLoc) c.execLoc`
— the PCALL round composes without a new configuration component.

**(B) The run-state supplies on the control.** `RunSup := ⟨sym : Nat, excl : Nat⟩`
(`core_run_state`'s `sym_supply`/`excluded_supply`, Core_run_aux.lean:356–357),
carried as `Ctl.sup`. NO E1 rule writes it (every rule threads
`ctl.sup` verbatim — `Ctl.upd_sup`, `Ctl.callPush_sup`); the driver lanes
leave it UNTIED at E1 (no `hsup` premise on `loop_step_frag`: the E1
rounds never read the supplies); Round's `MachineCtx.Embeds` ties both
fields to `dst.core_run_state0` (`sym`, `excl` — replacing the former
whole-record `runState` field) and `CerberusRound` fixes the successor
run state's two fields to the successor control's `sup`, so
`engine_step_matchU` certifies the supplies unchanged through every
round. Reasoning: E5's negative-action protocol draws fresh symbols and
excluded ids from the run state (`E.fresh_symbol`,
`E.fresh_excluded_id`, core_reduction.lem:1298–1301); designing the
field now means E5 adds RULES (writers) and driver TIES, not a
configuration re-shape of every statement — the shape is final at E1.
Design caution for E5 (E1 range audit N-1, added 2026-09-05 in E2):
`prodCtl.sup = default` (ProdEntry.lean) is a PLACEHOLDER — the
production initial state has `sym_supply := sup` (generated
`Core_run_aux.lean:400`); sound now because the driver lanes leave the
supplies untied, but E5's tie needs `prodCtl sup` and an `hsup` premise
threaded through `loop_step_frag`/`DriverSafeCtl`/`DriverDoneCtl` (the
nine production statements' texts stay).
The value-form change rides along: `SpikeValA` (a value WITH its two
static annotation lists), `ofValA`/`toValA`, `SpikeValA.erase : SpikeValA → SpikeVal`,
`CoreRVal.w : SpikeValA` with `CoreRVal.sv := w.erase` (the WP
postconditions read `w.sv`); the RETURN plugs `ofValA (.pure a [] v)`
(the engine's `mk_value_e` keeps the outer list and empties the inner).

## 7. Deviations and decision points ([AGENT])

   generalized"): once the LETS-ANNOT beta at the symbol binder is
   mirrored, the head restriction has no purpose; `Frag.sseq_sym`
   admits any fragment head. Its pins `BareHead.step` (trio-exact,
   REMOVED from the pin list) and the unpinnable
   `BareHead.decomp_call_root` are gone — a census REMOVED entry the
   operator should see.
2. `Frag.esize_step_bound` DELETED (no consumer after the re-cut;
   `Frag.pot_step_bound` is the live bound). `MachineCtx.currentLoc`
   DELETED (its role moved to `Ctl.curLoc`). `Step.CallOf.ne_same_ctl`/
   `Step.call_ne_same_ctl` replaced by `…_ne_same_κ`/`…_ne_upd` (a call
   changes κ; the general arm changes only the location).
3. `wps_bound`'s post is `.pure w.val`, not "the same post" (§3).
4. The `sseq_sym` annotated-head row is NO-RULE, not RULE: E1 mirrors
   the step and admits the shape but adds no binder rule over annotated
   heads (E2's patterns bind annotated heads; no consumer needs it at
   E1 because `bound` drops the annotations before every emitted
   binder — `let strong a = bound(…)`).
5. `prodCtl` made `@[reducible]` (as `procCtl`/`prodCtx`): the
   readouts' controls (`⟨[], some mainSym, ℓ, lc, sp⟩`) unify with it
   by eta only when it unfolds; the four readout theorems
   (`fr_wp_readout`, `eo_wp_readout`, `cs_wp_readout`, `cs_twp_readout`)
   are generalised over `(lc : Loc) (sp : RunSup)` — a live-state-forced
   statement change (census §9).
6. The corpus speedbump is a gate step (FULL mode), not a standalone
   script; the plants are permanent negative fixtures so a vacuous
   instrument is loud on every run.
7. The census split "live-state forced" vs "annotation generalisation"
   is DERIVED by a marker scan (§9), not by reading each of the 583
   changed statements. ERRATUM (E1 range audit R-2, appended 2026-09-05
   in E2): the scan UNDER-counts the forced class — see §9's erratum.
8. Build-cost discipline: no single build or proof pass approached the
   tripwire; the longest observed passes were the full-package rebuilds
   after a `Step.lean`/`Soundness.lean` change (§8). No heartbeat or
   maxRecDepth option was raised anywhere; the Round.lean timeouts met

   ×5 constructor case explosion) and were removed by restructuring the
   proofs (hoisting `cases ctx <;> dsimp only [step_action]` before the
   value/`PePure` splits), not by options.
