- Location. `MallocListExhibit.lean` — `mlPost` (:811-813, verbatim):

- Tree's truth. Nothing in any of the four statements says the `ids` are
  pairwise distinct. Pure form: for `n ≥ 1`, `∃ ids, ids.length = n.toNat ∧
  ∀ id ∈ ids, DeadAt σ id` is implied by `∃ i, DeadAt σ i` (witness
  `List.replicate n.toNat i`) — I checked this shape elaborates against the
  tree (environment query: `⟨List.replicate n.toNat i, List.length_replicate,

  `Persistent` (`deadRegion_persistent`, Heap.lean:3796) and `IProp` is
  affine, so `deadRegion id a 16 ⊢ deadRegions (List.replicate n id)`; the
  post of `ml_wps`/`ml_wpt` is therefore, for `n ≥ 1`, interderivable with
  `⌜w = .pure Vunit⌝ ∗ ∃ id a, deadRegion id a 16`. The K4 dispose exhibit
  stated `i₁ ≠ i₂` explicitly; this exhibit does not state the analogue.
- The claims. Module header (:76-80): "the engine DELIVERS `Vunit` … with

`loadM` (:1622-1665), `storeM` (:1667-1730), `allocateRegion` (:1533-1553),

pinned CerbMem.lean. The worker's §1.1 quotes are verbatim (checked line by

  `MetaCell.ty` docstring already says "records NOTHING").

  `isAtomicMemberAccess`, whose `| none => false` arm (:1620) fires at a
