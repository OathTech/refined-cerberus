## Slice 1 (P3.1) — the dependency-certified manifest and the layer cut

### 1.1 Measurement before design (what a cone check can and cannot see)

The generator's checks were chosen by MEASURING candidate checks on
the P2-green tree (throwaway scripts over the built environment;
the numbers below are from those runs, verbatim where quoted):

1. **`ConstantInfo.value?` returns `none` for theorems** in this
   toolchain (4.32.2). A traversal written against it silently sees
   NO proof bodies (measured: `exhibitA_engine` "value consts 0" via
   `value?`, 63 via an explicit `.thmInfo t => t.value` match). The
   generator matches the constructor explicitly; the Audit's
   `carriesAx` (statement-rooted, through definitions) is unaffected.
2. **Transitive cone membership of a `Step` CONSTRUCTOR is
   VACUOUS.** Every consumer's full proof cone contains ALL 24 `Step`
   constructors — `exhibitB_engine` (a store-only program), `fib_certified`
   (no heap at all), `alloc_two_creates_wps` alike. Cause, measured
   by entry-edge tracing: every `cases`/inversion on `Step` names
   every constructor (edges `Step.casesOn → Step.*`, `Step.rec →
   Step.*`, and the inversion lemmas `Step.store_inv`/`val_elim`/
   `case_inv`/`create_inv → Step.*` — the dependent elimination
   re-builds indices with constructor terms), and every WP mention
   reaches those through the `Language` instance (`primStep := Step
   …`, `val_stuck` via `Step.toVal_none`). Excluding the auxiliary
   recursors does not help (the inversion lemmas remain). So the
   charter's "logical rule's cone contains the relational rule" is
   NOT implementable as a discriminating cone test in Lean 4, and the
   generator does not pretend to (manifest Notes 8a).
3. **Transitive cone membership of a Core SYNTAX constructor is
   equally vacuous** (every consumer reaches `Esseq, Ewseq, Esave,
   Eif, Erun, Ecase, Eannot, Ememop, Epure, Eaction, PEsym, PEval,
   Store0, Load0, PtrEq` — through `esize`/`Frag`/`Decomp`, which
   match over the whole AST).
4. **Cone membership of a public RULE is discriminating.** Measured
   rule sets, e.g.: `exhibitB_engine` → `{wp_store}` only;
   `case_certified` → `{wps_case_value, wps_ofVal, wps_unfold,
   wps_sound}`; `fib_certified` → `{wps_pure, wps_if_true, wps_run,
   wps_ofVal, wps_unfold, wps_if_false, wps_save, wps_sound}`;
   `alloc_two_creates_wps` → contains `wps_create`, NO launcher.
5. **Cone membership of an adequacy LAUNCHER is discriminating**:
   `alloc_two_creates_wps`/`alloc_create_wpt`/`struct_create_store_wps`/
   `progAProd_wpt`/`ctrProd_wpt`/`lrProd_wpt` reach NO launcher
   (they are rule-level); every engine-facing export reaches exactly
   its lane's launchers (e.g. `exhibitA_prod` → `{prod_run_eqJ,
   launchResources, wpt_driver_done_alloc}`; `struct_create_store_adequacy`
   → `{launchResources, wps_sound, spike_step_adequacy_alloc,
   engine_adequacyU_alloc, spike_engine_adequacy_alloc}`).
6. **A STATEMENT-ROOTED syntax witness is discriminating** when the
   traversal expands only definitions whose type is Core syntax
   (expr/pexpr/action/pattern/file/the runtime tuple/thread literal)
   plus the compiled-pattern auxiliaries of those definitions:
   `fib_certified` → `{Esave, Eif, Erun, Epure, PEsym, PEval}` (no
   `Store0`); `exhibitB_engine` → `{Eaction, PEval, Store0}`;
   `alloc_create_launch_smoke` → `{Eaction, PEval, Create}`;
   `case_certified` → `{Ecase, Epure, PEsym, PEval}`. A definitions-
   only traversal WITHOUT the syntax-type restriction is vacuous for
   the rule-level theorems (their statements mention the judgments,
   whose definitions reach the whole AST).
7. **The layer cut holds today.** With the cut = every declaration of
   {Rules, Wps, Wpt, Adequacy, TotalAdequacy, ProdLoop, ProdEntry}
   minus the operational names, plus the two Lang instances, ALL 608
   declarations of the 12 positive-exhibit modules reach no
   operational name (`clean 608 dirty 0`). The crossing points
   actually hit, grouped (load-bearing = transitively reaches an
   operational name): Rules `wp_store, wp_sseq, wp_load,
   exhibitC_triple, spike_wp_wand, stateInterp_readout`; Wps the
   `wps_*` rules + `wps, wps_sound, blockSpecs, blockSpecs_intro`;
   Wpt the `wpt_*` rules + `wpt, wpt_mono, wpt_mono_Ls, blockSpecsT,
   blockSpecsT_intro, blockSpecsT_mono`; Adequacy `drive, driveJ,
   driveU, SemTriple, ProvenTriple, semantic_triple_sound,
   semantic_frame, spike_engine_adequacy(_alloc), engine_adequacyJ,
   cells_readout`; TotalAdequacy `wpt_engine_boundU/J(_alloc),
   wpt_strongly_normalizing, readoutPost(_mono/_annot_absorb)`;
   ProdLoop `wpt_driver_done(_alloc)`; Lang `instLanguageCoreRtMemEmptyCoreRVal,
   instIrisGS`. Heap reaches no operational name (63 pure helpers
   hit, 0 load-bearing) and needs no approval; DriverCollapse is hit
   by nothing directly. `driveJ_step` (Adequacy) and `driverDone_step`
   (ProdLoop) live INSIDE cut modules and are excluded from the cut
   by name — the module-level cut alone would have approved them.
8. **Import-graph fact used for pruning**: Step, Soundness, Heap,
   Lang, StmtProbe import none of the target modules; DriverCollapse

   assertion caught the first draft, which had listed it as a leaf:

### 1.2 The design (as installed — `scripts/capability_manifest.lean`)

Per row, STAGED fields: `synCtors` (Core AST constructor(s), the
execution-witness alternatives) / `mirror` (Step constructors;
coverage DERIVED as before) / `logic` (the public PARTIAL rules) /
`engineMatch` / `partialLane` (the generic adequacy theorems) /
`adequacyConsumers` (engine-facing partial) / `localConsumers`
(rule-level, never claimed as adequacy) / `total` (rules,
derivations, engine-facing consumers) / `prod` (consumers) /
`prodRequires` (extra names every production consumer must carry —
create: `wpt_create`, `launchResources`).

Checks, all fail-closed (every failure is collected and the run
throws with all of them; gate 4 is red on a throw):

- EXECUTION WITNESS: every public rule and every listed consumer's
  STATEMENT reaches one of the row's syntax constructors through
  program-valued definitions (`stmtSyntax`).
- RULE DEPENDENCY: adequacy/local consumer cone ∋ a partial rule
  (local: partial or total); total derivation/consumer cone ∋ a total
  rule; production consumer cone ∋ a rule of the row.
- ADEQUACY DEPENDENCY: adequacy consumer cone ∋ an approved PARTIAL
  launcher; total consumer ∋ a TOTAL launcher; production consumer ∋
  a PRODUCTION launcher (explicit, existence-checked sets).
- PRODUCTION REQUIREMENT: production consumer cone ∋ each
  `prodRequires` name.
- THE LAYER CUT + DIRECT-REFERENCE BAN over EVERY constant of the 12
  positive-exhibit modules: DFS from the body, stopping at approved
  crossings (cut modules minus operational names, plus the Lang
  instances), failing with the PATH on any operational name
  (`Step.*` namespace, `engineSteps*`, `outcomesU`, `dischargeStep*`,
  `step_ctx_*`, `stepDischarge_*`, `Decomp.*`, `Redex.*`,
  `driveJ_step`, `driverDone_step`, `loop_step_frag`,
  `engine_step_matchU`, `engine_complete*`, the P3.2 names); and no
  body names `Step.*`/`engineSteps_*`/`driveJ_step`/`driverDone_step`
  directly.
- SOUNDNESS OF THE PRUNING: every target lives in a target module;
  no leaf module imports a target module (import closure from the
  environment header) — else throw.

Cone computation: the dependency table is filled lazily and
memoized (`DepM`); the cone is the transitive closure over the
package's own constants (foreign constants cannot name ours — the
import graph is acyclic), not expanding the leaf modules (sound by
the assertion above; skips the certification's giant terms). Run
time: ~130 s of which ~88 s is the import.

### 1.3 The instrument's first catches on the live tree (manifest corrections)

Running the staged checks against the P2 manifest's attributions
found THREE false lane claims, corrected in the row specs (the
generator would otherwise throw):

- `save` production lane listed `counter_loop_certified_production`
  and `list_reverse_certified_production`: NEITHER cone contains
  `wpt_save`. Their `save` is the never-entered registration site
  (the untaken sseq arm; the loop is entered by `run` against the
  driver-collected label), so no save rule is needed by the proof.
  Removed; `fib_certified_production` (which does execute its save)
  stays.
- `pure-sym` production lane listed `counter_loop_certified_production`:
  its cone has no `wpt_pure` (the counter exits through a bare
  value). Removed.
- The create row's single `consumer` cell mixed local rule-level
  theorems with engine-facing ones; split into `adequacyConsumers`
  (`struct_create_store_adequacy`) and `localConsumers`
  (`alloc_two_creates_wps`, `alloc_create_wpt`,
  `struct_create_store_wps`); `alloc_create_launch_smoke` is the
  TOTAL lane's engine-facing consumer; `progAProd_wpt`/`ctrProd_wpt`/
  `lrProd_wpt` are total DERIVATIONS.

Honesty additions in the same pass: `exhibitA_total` joins the total
lane of value/store/load/sseq/annot (it is the P2-retired trace's
total successor; its cone carries `wpt_engine_boundU` + the wpt
rules); the store/load rows list the generic subrange rules among
their partial rules (list-reverse and the struct client consume only
those); `struct_create_store_adequacy` joins the store/sseq-sym/
store-op adequacy consumers; `list_reverse_certified` joins save's.
