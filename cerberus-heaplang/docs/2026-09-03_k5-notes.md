## 1. THE RULES — what the engine checks at an untyped allocation, and the rules that carry it

### 1.1 The engine's arms (CerbMem.lean, the pinned tree; verbatim)

`isInBounds` (:1475):
```
def isInBounds (alloc : Allocation) (addr size : Int) : Bool :=
  addr >= alloc.base && addr + size <= alloc.base + alloc.size
```
`isAtomicMemberAccess` (:1609-1620) — the ONLY place the allocation's TYPE
enters the access path, and it is `false` at an untyped allocation:
```
def isAtomicMemberAccess (tagDefs : TagDefs) (alloc : Allocation) (lvalueTy : ctype) (addr : Int) : Bool :=
  match alloc.ty with
  | some allocTy =>
    match allocTy with
    | Ctype _ (.Atomic _) =>
      -- impl_mem.ml:692-703 (the type-equality conjunct deals with a
      -- padding-free first member)
      !(addr == alloc.base && (sizeofCtype tagDefs lvalueTy : Int) == alloc.size
        && ctypeEqual lvalueTy allocTy)
    | _ => false
  | none => false
```
`loadM`'s concrete-pointer arm (:1644-1664):
```
    | .PV (.Prov_some allocId) (.PVconcrete _ addr) =>
      -- impl_mem.ml:1644-1664
      if st.deadAllocations.contains allocId then
        fail_ (MerrAccess LoadAccess DeadPtr)                             -- impl_mem.ml:1645-1650
      else match st.allocations.get? allocId with
```

MEASURED ANSWER to the brief's question. At a region (`allocateRegion`,
:1533-1553, records `ty := none`, `isReadonly := IsWritable`, pushes the
base onto `dynamicAddrs`): a `loadM`/`storeM` at ANY ctype `ty` succeeds
whenever the id is not dead (load) / the record is present, the accessed
range `[addr, addr + sizeof ty)` lies within `[base, base + size)`, the
value is type-compatible (store), and the decode is not a `_Bool` trap
(load). There is NO effective-type check (the concrete model tracks none),
NO check relating `ty` to the allocation's type (`isAtomicMemberAccess`'s
`none` arm), and NO alignment check anywhere on either path. So there was
nothing for the rule to mirror beyond what the seams already state: the
accessed type enters only through its SIZE (the bound) and its decode/
serialization (the value). The rules therefore hold at ANY `vty` at ANY
`off` with `off + sizeof vty ≤ n`.

### 1.2 The typed region view (Heap.lean, section "The typed region view")

`regionView` (K1) was byte-only (bound `off + bs.length ≤ n`). The typed
reading is `pointsToView` with `regionCell a n true` for `objCell tds a aty
true false` and `n` for `sizeofCtype tds aty` (verbatim):
```
def typedRegionView (tds : CerbTags.TagDefsMap) (id a : Int) (n off : Nat) (dqm dqb : DFrac)
    (vty : ctype) (bs : List CerbMem.AbsByte) : IProp GF :=
  iprop(metaOwn id dqm (regionCell a n true) ∗
    ⌜off + CerbMem.sizeofCtype tds vty ≤ n ∧ bs.length = CerbMem.sizeofCtype tds vty⌝ ∗
    bytesOwn (a + (off : Int)) dqb bs)
```
Laws (each the object law's proof under the substitution): `typedRegionView_iff`
(`.rfl`), `typedRegionView_regionView` (`typedRegionView … vty bs ⊣⊢ regionView
… bs ∗ ⌜bs.length = sizeof vty⌝` — the typed view IS the untyped view at a
type-length image), `typedRegionView_split`/`typedRegionView_join`
(`pointsToView_split`/`_join` at the region cell: a region as a struct of
typed fields, metadata fraction split, bytes split at the list
decomposition), and the two carve laws the whole-region faces use —
`regionOwn_carve` (`regionOwn id a n dq bs ⊢ ⌜bs.length = n⌝ ∗
typedRegionView tds id a n off dq dq vty ((bs.drop off).take (sizeof vty)) ∗
bytesOwn a dq (bs.take off) ∗ bytesOwn (a + off + sizeof vty) dq ((bs.drop
off).drop (sizeof vty))`, metadata WHOLE, no fraction arithmetic) and
`regionOwn_uncarve` (the converse at any `pre mid suf` with `pre.length = off`
and `(pre ++ (mid ++ suf)).length = n`). The design choice to keep the
metadata whole and split only bytes is `wps_load_cell_at`'s (the object
stratum's interior rules do the same); it is why the exhibit's list
predicate can own whole regions (`regionOwn … (.own 1)`) and still access
fields.

### 1.3 The atomic rules (Rules.lean, section "THE REGION ACCESS RULES"; verbatim)

## 7. Corrections / measurements against the brief

- The brief asked whether the engine refuses typed access to untyped
  allocations "in some way (an effective-type check)" and to mirror it if
  so. MEASURED (§1.1): it does not; the only type-reading check
  (`isAtomicMemberAccess`) is `false` at `none`; no alignment check. The
  rules carry exactly the size bound and the value facts, nothing more.
- The brief's view design ("carved into typed views at offsets exactly as
  `pointsToView` carves an object") is met by `typedRegionView` +
  `typedRegionView_split`/`_join`; the exhibit does NOT use the typed
  split (it would need `.own (q₁ + q₂)` fraction arithmetic on the
  metadata) but the whole-region carve (`regionOwn_carve`/`_uncarve`,
  metadata whole) — the same route `wps_load_cell_at` takes for objects.
  Both are public; the split laws have no exhibit consumer yet (they are
  laws, not rules; the manifest tracks rules).
- The brief's "`_eval` operand forms if the object rules have them": the
  object `_at` rules have none of their own — `wps_load_eval`/`wps_store_eval`
  are pointer-generic and serve the region rules unchanged (the exhibit's
  six operand evaluations go through them). "`_plain` if annotations are
  delivered": the `_at` rules deliver `SpikeVal.annot [DA_pos [] fp] v`, as
  the object `_at` rules do, and like them have no `_plain` twin (only the
  whole-cell `wps_store`/`wps_load` have `_plain` forms, QA-1).
- The brief's exhibit: "a program that `alloc`s n nodes from one linear
  budget (`allocBudget_split`, as K4's loop), links them by typed stores,
  then walks and `free`s each" — delivered as ONE label with two phases
  (§2, the design decision), the free through `wps_free` (not
  `wps_free_emp`) so the post carries the dead knowledge. "Optionally a
  region-list reverse or length if cheap" — not done (not required).
- The value field is written at a SYMBOLIC integer (`store(long, q, i)`,
  the first symbolic-integer store in an exhibit: `memValueFromValue` at
  `Vobject (OVinteger ival)` and `memValueToBytes`'s `MVinteger` arm are
  constructor matches, so `rfl` closes `hmv`/`compat`/`fpm`/`bytes_fpm` at
  any `v`), but its decode is not tracked (§2). Honest limit, recorded.
