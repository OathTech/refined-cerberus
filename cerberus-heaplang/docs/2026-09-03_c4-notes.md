## 2. The one fragment change: `BareHead.call` (forced, [AGENT])

The design note's fib body binds a call's result at the plain-symbol
binder, `let x = fib(n−1) in …`. `Frag.sseq_sym` restricts that binder's
head to `BareHead` (fragment closure 2026-09-02: a literal, `create`,
`alloc`, the `PtrEq` memop — the bare-value producers, so the LETS-ANNOT
beta at the binder is unreachable), and a call redex was not one. The
alternatives measured and rejected: the `Specified`-binder `sseq_spec`
needs a LOADED return value, `pure(Specified(x + y))`, whose `PEctor
Cspecified` is outside the covered operand grammar `PePure` (an evaluator
extension + its certification); a `run`/`save` cannot carry an expression.
So `BareHead` gains

```lean
  | call {ra : core_run_annotation} {f : sym} {pes : List (generic_pexpr Unit sym)}
      (hpes : ∀ pe ∈ pes, PePure pe)
      (hdep : ∀ pe ∈ pes, peDepth pe ≤ lemDefaultFuel) :
      BareHead (callRedex ra f pes)
```

— the same operand grammar as `Frag.call`. WHY IT IS A BARE-VALUE
PRODUCER: RETURN plugs `Expr e_annots (Epure (mk_value_pe cval))`
(Core_reduction.lean:484 col 2276), the mirror `Step.ret` plugs `Expr []
(Epure (Pexpr [] () (PEval v)))` after `Step.ret_annot` has stripped an
annotated callee value (C2), so the binder's head after the return is
`val_pure` — the LETS-ANNOT beta stays unreachable. The four `BareHead`
lemmas gain a case each: `not_annot` (`simp`), `redex` (`Redex.call`),
`step` (vacuous: `Step.call_ne_same_ctl` — a call takes no
control-preserving step), `frag` (`Frag.call`). `BareHead.no_call`
(Adequacy.lean, "a `BareHead` never decomposes to a call") became FALSE
and is replaced by `BareHead.decomp_call_root : BareHead e → Decomp e ctx
(callRedex ra f pes) → ctx = CTX` (the one call shape is the root redex);
its consumer `Decomp.frag_plug_call'`'s `sseq_sym` case now plugs the
bare value at the root: `Frag.sseq_sym (.val_pure v) (.val_pure v) hf2`.
Mirror completeness is untouched: `complete_call` classifies a call at ANY
decomposition (the sym-binder frame included), `complete_beta_sym` binds
the bare value after the return; no residual arm is added; the manifest's
constructor set is unchanged (`BareHead` is a side predicate). `Frag.step`,
`Frag.decomp`, `Frag.pot_step_bound`, `Frag.stateInert_step` at `sseq_sym`
were already closed against the call (the C2/C3 `hcall.ne_same_ctl`
arms).

The sum `x + y` is computed by the fragment's binder for pure computation,
`save r(z := x + y) in pure(z)` (the C3 smoke's idiom): `pure(x + y)` is
not in `Frag` (`Frag.pure_sym` only). Its label `r` is REGISTERED by the
shipped registration in `fib`'s fiber (`collect_saves_frBody`, `rfl`) and
never jumped to (`frLs`/`frLsT` are `⌜False⌝`; `FragProcs.labels` holds:
`pure(z)` is in the cone).


ITS SHAPE: strong induction on the budget `k`, in continuation-passing
form over the ambient control — the driver-level twin of `wpt_sound_cps`
(Wpt.lean, C3), with two differences forced by the pure conclusion:
(i) the CONTINUATION BUDGET `kc` is ADDED to every conclusion (`k + kc`),
so that a callee's leftover budget and its caller's continuation budget
compose additively — the collapse into Iris TWP needs no such
bookkeeping, the pure driver fact does: at the callee's value with
remaining budget `k'`, its continuation must deliver within `k' + (k'' +
kc)` where `k''` is the caller's continuation budget from the call
clause's split, and `DriverDoneCtl.mono` (the budget is an upper bound)
closes the arithmetic; (ii) the continuation receives the remaining budget
`k'` with `deliveryCost w ≤ k'`, the state interpretation and the
postcondition. The cases: VALUE — the continuation at `SameTail.refl`;
JUMP — the target's budget `m ≤ k'` by `wpt_mono_k`, one round
(`driverDoneCtl_step`), the IH; STEP — as the single-procedure lane
(`Step.ctl_eq`: control-preserving), one round, the IH; CALL —
`wpt_call_eq` gives `lookupProc … f = some (params, body)`, the arity, the
arguments, the split `1 + m + k' ≤ k`, the precondition and the caller's
continuation; `procSpecsT` gives the callee's label spec, block specs and
body judgment at budget `m`; the IH is applied to the body at the pushed
control `⟨(some p, ctx) :: κ, some f, push_exec_loc f M₀.currentLoc ℓ⟩`
with continuation budget `k' + kc` and the continuation that performs THE
RETURN — `SameTail` gives the callee's final env `ev0' :: ev0 :: evs`;
`Step.ret` (after `Step.ret_annot` for an annotated value) is one or two
rounds (`driverDoneCtl_step` at `Frag.val_pure`/`.annot`, `esize_ofVal_le`)
landing on `apply_ctx ctx (pure v)` at the popped env `ev0 :: evs` and
the control `⟨κ, some p, ℓ'⟩`, in the cone by `Decomp.frag_plug_call`/
`pot_plug_call_le` (the C2 plug lemmas), where the IH is applied AGAIN at
`k'` with the outer continuation; the call round itself is one
`driverDoneCtl_step`, and `1 + m + k' ≤ k` pays for it. Every round is
`loop_step_frag` at the LIVE control (DriverCollapse.lean, C2), via

## 6. The budget: `fibRounds` and the arithmetic

```lean
def fibRounds : Nat → Nat
  | 0 => 3
  | 1 => 3
  | n + 2 => fibRounds (n + 1) + fibRounds n + 9
```

Per activation, from the rules used in `frBody_wpt`: the guard round
(`wpt_if_true`/`_false`, 1); at the base case PURE + delivery (`wpt_pure`,
2) — total 3; at the recursive case `wpt_seq_sym`'s `k1 + k2` with `k1 =
1 + m₁ + 1` for `lets x = fib(n−1)` (`wpt_call_root` with `k' = 1`: the
call round, the callee's budget `m₁ = fibRounds (n−1)`, and the returned
BARE value's delivery cost 1 — which `wpt_seq_sym` spends on the binder's
beta, measured in its value case: at `k1 = m + 1` the beta is the `+1` and
the leftover `m` is weakened away), the same for `lets y = fib(n−2)`, then
the `save` (`saveEntryCost = 2` at an evaluated initializer: the SAVE-EVAL
and SAVE rounds) and PURE + delivery (2): `(m₁ + 2) + ((m₂ + 2) + 4) + 1 =
m₁ + m₂ + 9`. So the design note's estimate "≈ 9 rounds plus the two
recursive activations" is EXACT (the note called it an estimate; the
recurrence `fibRounds(n) = fibRounds(n−1) + fibRounds(n−2) + 9` is the
one it wrote). `main` is `wpt_call_root` at `m = fibRounds n`, `k' = 1`:
`fibRounds n + 2`; `prod_run_eqJ_procs` adds `+ 2` (the done-recording and
drain iterations), hence `hfuel : fibRounds n.toNat + 4 ≤
CerbFuel.driverFuel`. Closed form (`fibRounds_closed`, two-step
induction): `fibRounds n + 9 = 12 · fib (n + 1)`, so `fibRounds 33 =
68434635` and `fibRounds 34 = 110729571`: `n ≤ 33` is in the shipped
budget `10^8` (the note's "`n ≤ 25` at `10^6`" was at `lemDefaultFuel`;
the drive cone's budget has been `CerbFuel.driverFuel = 10^8` since the
