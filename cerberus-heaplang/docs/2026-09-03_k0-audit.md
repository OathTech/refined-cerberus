### N-1 (Note, load-bearing for K3) — the K3 plan "a `MetaCoh` clause tying the dynamic flag to `dynamicAddrs`" is sound in ONE direction only; the engine admits `free` of a `create`d object

- Location: `2026-09-03_k0-notes.md` §7 ("K3's `free` rule will take
  'this allocation is dynamic' from the metadata cell ... with a
  `MetaCoh` clause tying it to `dynamicAddrs`"); Heap.lean section
  header ("K3's `free` rule takes 'this allocation's base is in
  `dynamicAddrs`' from the per-allocation metadata cell"); design spike
  §0 ("so `free(p)` of a `create`d object is UB179a").
- Tree's truth (engine, by reading): after `create` of an object at base
  `B` the cursor is `B` (`lastAddress := alignedAddr`, :1522). A
  subsequent `allocateRegion` with `sizeN = 0` computes `addrAfterSize
  := B - 0`, `alignedAddr := alignDown B.toNat align` (:1539-1540); when
  `B` is a multiple of `align` this is `B ≠ 0`, so the region succeeds
  with `allocations.insert allocId { base := B, size := 0 }` and
  `dynamicAddrs := B :: …` (:1547-1548). `MemWF` survives (`disj`: `B +
  0 ≤ B`; `dyn_disj`: `B ≤ B` — this is precisely why the components are
  inclusive). Now `killM loc true p_created`: `addr != alloc.base` is
  false, `isDynamic && !st.dynamicAddrs.contains alloc.base` is FALSE
  (:1573), so the success arm fires (:1576-1578): the engine frees a
  `create`d object under `free` with no UB. (Mirrors the OCaml
  `List.mem` check; not a port bug — an engine fact.)
- Consequence: a `MetaCoh` clause `dynamic = false → base ∉
  σ.dynamicAddrs` is NOT preserved by `allocateRegion` and cannot be
  carried; only `dynamic = true → base ∈ σ.dynamicAddrs` is (the list
  only grows). The spike's "free of a created object is UB179a" is
  state-dependent, which K3's completeness classification of `free`
  must state as such. Nothing in K0 is wrong; the K0 record's forward
  plan needs the qualification.
- Fix (a statement for the K3 brief): "The metadata `dynamic` flag is
  tied to the engine by the one-directional clause `dynamic = true →
  base ∈ σ.dynamicAddrs`; `free` of a non-dynamic allocation is
  classified UB179a only under the additional state fact `base ∉
  σ.dynamicAddrs`, which is not an invariant."

**`dyn_disj` on the new record after `allocateRegion`.** `allocateRegion`
produces exactly (:1543-1550): `allocId := st.nextAllocId`; `alloc :=
{ base := alignedAddr, size := sizeN.toNat, prefix_ := pref }` (so `ty :=
none`, `isReadonly := .IsWritable` by default); `st' := { st with
nextAllocId := allocId + 1, lastAddress := alignedAddr, allocations :=
st.allocations.insert allocId alloc, dynamicAddrs := alignedAddr ::
st.dynamicAddrs }`; then `writeBytesTo st' alignedAddr (List.replicate
size {Prov_none, none, none})`; result `PV (Prov_some allocId)
(PVconcrete none alignedAddr)`. The pushed address `a = alignedAddr` and
the new record `al` with `al.base = alignedAddr`: the component asks `a ≤
al.base ∨ al.base + al.size ≤ a`, and `a ≤ al.base` is `alignedAddr ≤
alignedAddr` — TRUE by reflexivity. The docstring "no dynamic address
lies STRICTLY inside a live allocation" is the accurate reading; a
region's own base is on the boundary, not strictly inside. The proof term
agrees: `MemWF.alloc`'s `dyn_disj` bullet handles `a = al.base` by `Or.inl
(Int.le_refl _)` and takes `hdyn : ∀ a, a ∈ dyn → a = al.base ∨ a ∈
σ.dynamicAddrs`, i.e. it is already general enough for `dyn :=
alignedAddr :: σ.dynamicAddrs`. **The hypothesised High does not
materialise.** Against pre-existing live records, `a = new cursor ≤ old
cursor ≤ their bases` (`Or.inl`); against later allocations, `their end ≤
then-cursor ≤ a` (`Or.inr`, via `dyn_lo`) — both in the proof.

**Missing vs the goal?** The goal names id discipline, live/dead
consistency, range disjointness of all live allocations, cursor bounds:
`live_lt/dead_lt`, `live_dead`, `disj`, `cursor_lo/la_wf` cover them
literally. Byte-range consistency (M-1's "at minimum" list): I AGREE with
the drop. `readBytesFrom` (:1462-1466) returns `{ prov := .Prov_none,
copyOffset := none, value := none }` for a missing key, `loadM` reads only
through it, and the bytemap is never enumerated, so "every allocated
address is mapped" is unobservable: both allocators write `replicate size
unspecified` anyway (:1529-1530/:1549-1550), so it happens to be true, but
a component with no consumer and no engine content is cruft. Not missing:
`Nodup deadAllocations` (true — `killM` checks `contains` first, :1566 —
but no consumer), a lower cursor bound (nothing needs it). Dynamic
component: `dyn_lo`/`dyn_disj` is what the engine maintains; the
stronger "every dynamic address is a live base" is false (verified), and
`Nodup dynamicAddrs` is false (two zero-size regions at the same aligned
cursor push the same address twice — the engine does not deduplicate).

### 3. Preservation, `create_fresh_global`, the K3 obligations

`applyMemM` (Step.lean:951-956) is `match f st with | (NDactive x, st') =>
some (x, st') | _ => none` — the active projection; killed and
nondeterministic outcomes are `none`, so a theorem over `applyMemM … =
some (r, σ')` is exactly "every active outcome". `MemWF.loadM` (Heap.lean
:1379-1395) unfolds `loadM`, splits every `prov`/`base` pair and every
`if`/`match` (`repeat' split at hrun`), and closes each arm by `of_fields
rfl…` (the single active arm returns `st`, :1640) or `cases hrun` (killed
arms). `MemWF.storeM` (:1439-1458) does the same for `storeM` at
arbitrary `lk`, closing the `isLocking = true` arm with `MemWF.map_allocs`
(the map at :1690-1693 preserves keys, and `hf : (f k a).base = a.base ∧
(f k a).size = a.size` holds for both branches of its `if`).
`MemWF.allocateObject` (:1460-1487) is at ANY `pref`, `align`, `reqAddr`,
`initOpt`: the `alignedAddr == 0` arm is `cases hrun`, the other is
`MemWF.alloc` at the padded size followed by `of_fields` through both
`initOpt` branches. These are genuine theorems over the engine's
definitions, not over the `_success` shapes; `MemWF.create` is the
`_success`-shaped corollary `CohG.create` consumes. All `#print axioms`
trio-exact (below).

Placement makes preservation FORCED for the rules: `CohG.wf` is a field of
the state interpretation, so any rule that changes σ under a present
cursor cannot be proved without re-establishing `MemWF` (`CohG.storeRange`
:2831-2832 via `writeBytesTo`; `CohG.create` :3057-3064 via
`MemWF.alloc`). The explicit `MemWF.loadM/storeM/allocateObject` are the
rule-independent engine-level statements. Both faces are present.

`create_fresh_global` (:1363-1371): conjuncts (1) `σ.allocations.get?
σ.nextAllocId = none`, (2) `σ.deadAllocations.contains σ.nextAllocId =
false`, (3) `∀ id al, get? id = some al → freshBase … + size ≤ al.base`.
(1)+(2) are the id-freshness half of the goal's "fresh" (unused live AND
dead). (3) is the right disjointness for a downward cursor: the new range
`[freshBase, freshBase + size)` ends at or below `lastAddress ≤ al.base`
for EVERY live `al`, tracked or not — `allocDisjoint new al` by `Or.inl`.
It does not mention `dynamicAddrs` (N-2: derivable from `dyn_lo`, not
stated). It cannot speak about erased dead ranges (the record is gone
after `killM`; the worker says so).
