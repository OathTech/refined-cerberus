## 2. THE INDEX: the current procedure, not the control (forced)

The brief asked whether the current procedure becomes a parameter. It
is the WHOLE index: `wps M p Ls Θ Ψ e ρ` with `p : Option sym` (the
engine's `current_proc_opt`; `none` at the straight-line profile), the
step clause quantified over the call stack and execution location
`(κ, ℓ)`, the configuration `⟨e, ρ, ⟨κ, p, ℓ⟩, M⟩`.

FORCING FACT: RETURN does not restore `exec_loc`. PCALL writes
`exec_loc := push_exec_loc psym th_st.current_loc th_st.exec_loc`
(Core_reduction.lean:484 col 18133); the RETURN arm (col ≈2276) writes
`current_proc_opt`, `env`, `stack0` and `arena` only — the pushed
location stays. So after a call and return the caller's continuation
runs at the control `⟨ctl.κ, ctl.proc, push_exec_loc …⟩`, which differs
from the call-time `ctl` in `execLoc`; a judgment indexed by the full
control could not be re-entered at the caller's continuation without a
control-retagging lemma over a Löb (a phantom index). Nothing is lost:
every C1/C2 rule was control-general (the C1 range audit), so every rule
restates with `p` in place of `ctl` and `M.labelsAt p` in place of
`M.labelsAt ctl.proc`; the pre-C3 judgment at `ctl` is the instance
`κ := ctl.κ, ℓ := ctl.execLoc` of the new one at `p := ctl.proc`,
`Θ := emptyProcSpec` (the new judgment is the stronger, control-general
statement; every old rule instance is recovered, §8).

Rule-level consequences: `wps_of_atomic`/`wpt_of_atomic` take `h : ∀ κ ℓ,
AtomicStep M ⟨κ, p, ℓ⟩ e ρ c P Q` (the atomic specifications are
control-general — `fun _ _ => store_atomic …` at every call site);
`wpt_det_step`'s `hstep`/`hdet` are quantified over `(κ, ℓ)` likewise.
The collapses and the adequacy exports keep `{ctl : Ctl} (hκ : ctl.κ =
[])` and read the judgment at `ctl.proc`.

## 3. `procSpecs`, `procSpecs_intro`, the call rule (verbatim)

```lean
abbrev procSpecs (M : MachineCtx) (Θ : ProcSpec GF) : IProp GF :=
  iprop(□ ∀ (f : sym) (params : List (sym × core_base_type)) (body : CoreExpr)
    (vs : List value) (ρ : EnvStack),
    ⌜lookupProc M.file M.extern f = some (params, body)⌝ -∗ ⌜params.length = vs.length⌝ -∗
    ∃ (Ls : LabelSpec GF),
      blockSpecs M (some f) Ls Θ (fun w _ => (Θ f vs).2 w.val) ∗
      ((Θ f vs).1 -∗
        wps M (some f) Ls Θ (fun w _ => (Θ f vs).2 w.val) body (procEnv params vs :: ρ)))

theorem procSpecs_intro (Lsₚ : sym → List value → LabelSpec GF)
    (hB : ∀ f params body vs, lookupProc M.file M.extern f = some (params, body) →
      params.length = vs.length →
      ⊢ blockSpecs (GF := GF) M (some f) (Lsₚ f vs) Θ (fun w _ => (Θ f vs).2 w.val))
    (hW : ∀ f params body vs (ρ : EnvStack),
      lookupProc M.file M.extern f = some (params, body) → params.length = vs.length →
      (Θ f vs).1 ⊢ wps (GF := GF) M (some f) (Lsₚ f vs) Θ (fun w _ => (Θ f vs).2 w.val) body
        (procEnv params vs :: ρ)) :
    ⊢ procSpecs M Θ

theorem procSpecs_empty : ⊢ procSpecs (GF := GF) M emptyProcSpec

theorem wps_call {Ψ : SpikeVal → EnvStack → IProp GF} {e : CoreExpr} {ctx : context}
    {f : sym} {pes : List (generic_pexpr Unit sym)}
    {params : List (sym × core_base_type)} {body : CoreExpr} {vs : List value}
    (ρ : EnvStack)
    (hc : callRedex? e = some (ctx, f, pes))
    (hf : lookupProc M.file M.extern f = some (params, body))
    (hlen : params.length = vs.length)
    (hvs : evalPexprs M.tagDefs M.extern ρ pes = some vs) :
    iprop((Θ f vs).1 ∗ (∀ (ret : value), (Θ f vs).2 ret -∗
        wps M p Ls Θ Ψ (apply_ctx ctx (Expr [] (Epure (Pexpr [] () (PEval ret))))) ρ)) ⊢
      wps M p Ls Θ Ψ e ρ

theorem wps_call_root {Ψ : SpikeVal → EnvStack → IProp GF} (a : List annot)
    (ra : core_run_annotation) (f : sym) (pes : List (generic_pexpr Unit sym))
    {params : List (sym × core_base_type)} {body : CoreExpr} {vs : List value}
    (ρ : EnvStack)
    (hf : lookupProc M.file M.extern f = some (params, body))
    (hlen : params.length = vs.length)
    (hvs : evalPexprs M.tagDefs M.extern ρ pes = some vs) :
    iprop((Θ f vs).1 ∗ (∀ (ret : value), (Θ f vs).2 ret -∗
        wps M p Ls Θ Ψ (Expr [] (Epure (Pexpr [] () (PEval ret)))) ρ)) ⊢
      wps M p Ls Θ Ψ (Expr a (Eproc ra (Sym f) pes)) ρ
```

`wps_call` is the clause (near-definitional; `▷` introduced); the design
note's `wps_call` is `wps_call_root` (`apply_ctx CTX e = e`). The label
specification of an activation is EXISTENTIAL inside `procSpecs` (the
client's `procSpecs_intro` supplies a table `Lsₚ f vs`): Hoare's rule
does not expose the loop invariants; the design note's `Lsₚ` as a
parameter of `procSpecs` was weighed and dropped for that reason (the
collapse's statement mentions no label table for the callees). The
label spec is per procedure AND argument list — a loop invariant inside
a body depends on the arguments (fib's on `n`).

The post is over the BARE value `w.val`: RETURN plugs `mk_value_pe
cval`, the annotation wrapper having been removed by REMOVE-ANNOT first
(`Step.ret_annot`), so the caller sees `pure ret` — the clause's
continuation is stated accordingly, and the callee's post ignores its
final env (RETURN pops it; §5).

Total twins: `ProcSpecT`, `emptyProcSpecT`, `procSpecsT` (`∀ … (m : Nat)
…, ∃ Ls, blockSpecsT M (some f) Ls Θ (Ψ_f) ∗ ((Θ f m vs).1 -∗ wpt M (some
f) Ls Θ m (Ψ_f) body (procEnv params vs :: ρ))`), `procSpecsT_intro`
(`Lsₚ : sym → Nat → List value → LabelSpecT GF`), `procSpecsT_empty`,
`wpt_call`/`wpt_call_root` with `(hk : 1 + m + k' ≤ k)` and the
continuation at budget `k'`.

## 4. `∀ ρ` over the caller's tail — FORCED, and free

`lookup_env` (Core_aux.lean:872, verbatim modulo whitespace): `fun x =>
match x with | [] => none | env1 :: xs => (match fmapLookupBy
(@mapKeyCompare b _) sym1 env1 with | none => lookup_env sym1 xs | some ret
=> some ret)` — it searches ALL frames top-down. A body's read of a
symbol its own frame does not bind resolves in the CALLER's frames (or,
on a total miss, in `file.funs` — the design note's Q5(4)). So the
specification of a body must hold at EVERY caller tail: `procSpecs`
quantifies `∀ (ρ : EnvStack)` and enters the body at `procEnv params vs
:: ρ` (`call_proc`'s `env := proc_env :: th_st.env`, Core_run.lean:93 /
Core_reduction.lean:484). It costs nothing in a body proof: `procEnv` is
`fmapAddBy`-built from empty (a `SymFrame`; at one parameter it IS
`envAdd x v fmapEmpty` — `procEnv_single`, `rfl`), every parameter read
is a head-frame hit (`lookup_env_head` + `envAdd_lookup`), and `update_env`
writes the head frame only (Core_aux.lean:868), so a body whose free
symbols are its parameters and `save`-bound locals never reaches the
tail. No closedness side condition enters the logic (the smoke's
`csF_body_wps` is stated and proved at an arbitrary `ρ`).

## 5. THE COLLAPSE — CPS over the ambient control, the one Löb, the return

```lean
def SameTail (ρ ρ' : EnvStack) : Prop :=
  ∀ ev0 evs, ρ = ev0 :: evs → ∃ ev0', ρ' = ev0' :: evs

theorem wps_sound_cps (p : Option sym) (Ls : LabelSpec GF) {Ψ : SpikeVal → EnvStack → IProp GF}
    (κ : List (Option sym × context)) (ℓ : exec_location) (e : CoreExpr) (ρ : EnvStack)
    (Φ : CoreRVal → IProp GF) :
    procSpecs M Θ ⊢
      iprop(blockSpecs M p Ls Θ Ψ -∗ wps M p Ls Θ Ψ e ρ -∗
        (∀ (ℓ' : exec_location) (w : SpikeVal) (ρ' : EnvStack), ⌜SameTail ρ ρ'⌝ -∗ Ψ w ρ' -∗
          WP (⟨ofVal w, ρ', ⟨κ, p, ℓ'⟩, M⟩ : CoreRt) @ Stuckness.NotStuck; ⊤ {{ Φ }}) -∗
        WP (⟨e, ρ, ⟨κ, p, ℓ⟩, M⟩ : CoreRt) @ Stuckness.NotStuck; ⊤ {{ Φ }})
```

The continuation `K` accepts every value the statement delivers, at a
final env with the frames below the head preserved (`SameTail ρ ρ'`)
and at ANY execution location `ℓ'` (the return does not restore it, §2).
THE ONE LÖB is here (`iloeb as IH generalizing %p %Ls %Ψ %κ %ℓ %e %ρ %Φ`;
`procSpecs` and `blockSpecs` are `□`, in the intuitionistic context —
iris-lean's `iloeb` puts the IH there too, `□ ▷ goal`, which the call
case uses TWICE). Cases:
- VALUE: `K` at `SameTail.refl`.
- JUMP: as before (`Step.run_of_jumpRedex`/`Step.jump_inv`); `K`
  composed with the jump step's `SameTail` (`Step.sameTail`, the
  `SameTail` form of C2's `Step.env_cons'`: every control-preserving step
  keeps the frames below the head).
- CALL (`Step.call` for reducibility, `Step.call_inv` for the unique
  successor): `procSpecs` at `(f, params, body, vs, ρ)` yields `Ls'`, the
  callee's `blockSpecs` and `(Θ f vs).1 -∗ wps (some f) Ls' Θ Ψ_f body
  (procEnv params vs :: ρ)`; the precondition comes from the clause; the
  IH applies to the body at the pushed control `⟨(p, ctx) :: κ, some f,
  push_exec_loc f M.currentLoc ℓ⟩` with the continuation `K'` that
  performs THE RETURN: `SameTail (procEnv params vs :: ρ) ρ'` gives
  `ρ' = ev0' :: ρ` (`SameTail.cons_inv`); a bare value takes `wp_ret`
  (`Step.ret`, its inversion `Step.ret_inv`: the value plugged into the
  captured context at the popped env `ρ` and the caller's procedure `p`,
  `ℓ'` riding), an annotated one `wp_ret_annot` then `wp_ret`
  (`Step.ret_annot`, `Step.ret_annot_inv`); the landing configuration
  `⟨apply_ctx ctx (pure v), ρ, ⟨κ, p, ℓ'⟩, M⟩` is the caller's
  continuation from the clause (`Hcont v`), collapsed by the IH AGAIN
  with the caller's own `blockSpecs` and `K`. This is where the one Löb
  and the frame stack meet; the call round's `▷` pays for both uses.
- STEP: the IH at the successor; `K` composed with `Step.sameTail`.

THE RETURN went through in the design note's shape; no obstacle. The
brief's concern — how `K` delivers the callee's post to the caller's
continuation — is answered by the env invariant: the callee's final env
is `ev0' :: ρ` as a THEOREM (`SameTail` threaded through the IH), so
RETURN's pop lands on the caller's `ρ` verbatim and the clause's
continuation (stated at `ρ`) applies. The design note's `Step.env_tail_eq`
is `Step.sameTail`.

## 6. The env-depth invariant as a lemma (the C2 audit's N-1)

```lean
theorem Step.env_depth {M : MachineCtx} {e e' : CoreExpr} {ρ ρ' : EnvStack}
```
