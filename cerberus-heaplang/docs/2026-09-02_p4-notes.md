## 1. P4.1 — the three allocation facts (R-06)

Heap.lean's header now states THE THREE ALLOCATION FACTS (after
RefinedC's `heap_mapsto` / `loc_in_bounds` / `alloc_alive` split):

1. LINEAR/FRACTIONAL BYTES — `bytesOwn`: `bytesOwn_append` (range
   split/join, pre-existing), NEW `bytesOwn_fractional` (split at a
   fraction sum, per byte — Boyland), NEW `bytesOwn_agree` /
   `byteOwn_agree`.
2. PERSISTENT ALLOCATION KNOWLEDGE — NEW `allocMeta tds id a aty :=
   metaOwn id .discard ⟨a, aty, sizeofCtype tds aty⟩` and NEW
   `locInBounds tds id a aty off n := allocMeta … ∗ ⌜off + n ≤ size⌝`,
   with `Persistent` instances (`allocMeta_persistent`,
   `locInBounds_persistent` — THE PERSISTENCE LAW; `allocMeta_dup`
   states it as `P ⊣⊢ P ∗ P`), `allocMeta_agree`, `metaOwn_persist`,
   `pointsToView_persist` (a view trades its metadata fraction for
   persistent knowledge; the bytes are untouched),
   `pointsToView_locInBounds` (a persistent-metadata view yields its
   bounds fact and keeps itself — the persistence law at work).
   THE BUNDLES KEEP THE METADATA AT A FRACTION `dqm`: full metadata
   ownership is the per-allocation exclusivity anchor
   (`metaOwn_ne` → `bigSepM_own_disjoint`, Adequacy.lean:1142) that
   the semantic-triple frame theorem needs; in the donor that anchor
   is the killable `alloc_alive`. Named as a deliberate divergence in
   the header. The pure bounds conjunct stays inside `pointsToView`
   (absorbing it into `locInBounds` would force persistent metadata
   into the bundle — the exclusivity anchor forbids it); `locInBounds`
   is obtained FROM a view (`pointsToView_locInBounds`) instead.
3. NO LIVENESS/FREEABILITY TOKEN — documented: no rule updates a
   metadata cell (`metaHeap_alloc` mints; nothing writes); the named
   mover (kill joins the fragment → alloc_alive/freeable split, the
   anchor moves there) is recorded in the header.

Also NEW at the heap layer: `cellPtr_inj` (moved from Exhibit.lean,
which had a private copy), `cellPtr_arrayShift` (PROVENANCE-PRESERVING
POINTER SHIFT: `arrayShiftPtrval tds (cellPtr id a) ty (integerIval k)
= cellPtr id (a + k * sizeof ty)` for every NON-VOID `ty` — the
engine's `PVconcrete` arm has a GNU byte-granular void exception, hence
the `hty` premise), `pointsToView_fractional`, `pointsToView_agree`
(METADATA/BOUNDS AGREEMENT of two views of one allocation),
`cellOwn_fractional`, `pointsToCell_fractional` (the textbook law),
`pointsToCell_agree`, `pointsToCell_combine` (agreement + join).
Wps.lean: NEW `wps_fupd` (postcondition-modality absorption, iris
`wp_fupd` — the rule that lets a client perform a ghost update inside
the statement logic). Adequacy.lean: NEW `cellOwn_readout` /
`pointsToCell_readout` — the PUBLIC single-cell readouts; the three
clients that opened the state interpretation themselves
(ArrayExhibit `arr_wp_readout`, StructExhibit `struct_wp_readout` +
`struct_create_store_adequacy`, LoopExhibit's local `cell_readout`)
now consume them.

"Within bounds" (the charter's wording for the shift law): the shift
is unchecked arithmetic in the concrete memory model
(CerbMem `arrayShiftPtrval`); bounds are enforced at the ACCESS by the
in-bounds conjunct every view carries — so a shifted pointer is usable
exactly when the sub-range it names is in bounds. No decorative bounds
lemma was added (it would have had no consumer). The three per-type
shift facts (`arrayShift_cellPtr` int, `arrayShift_cellPtr_long`,
`arrayShift_cellPtr_long_two`) are now instances of the generic law.

## 6. Borderline observations

1. `struct_x_read_persist_wps` states the bounds fact as `locInBounds …
   fieldX (sizeofCtype M.tagDefs intTy)` rather than `… 4`: the proof
   mode matches at reducible transparency and `sizeofCtype M.tagDefs
   intTy` does not unfold to `4` there (it is `rfl` at default
   transparency — `intTy_size`). Same reason the view client rewrites
   the program to literal field offsets `0`/`8` (`fieldX`/`fieldY` are
   plain defs) and unfolds `fiveBytes`/`sixBytes` at the join.
2. `cellPtr_arrayShift` carries `hty : ∀ q, ty ≠ Ctype q .Void0`: the
   engine's `arrayShiftPtrval` treats `void` as a byte-granular shift
   (`elemSize = 1`), so the generic law is false there.
3. `ProdLoopExhibit`'s production label spec keeps a framed shape,
   `frameLsT (lrCellFrame ∅) (lrLsT …)` — the empty cell frame is
   vacuous (`bigSepM_empty`), retained so `lrPost_readout` applies
   unchanged; the invariant itself is unframed.
4. The inventory instrument's category split (Ghost vs Plan) and the
   `pointsToCell_cellOwn_iff` exclusion are judgment calls recorded
   here; both the BEFORE and AFTER lines above use the same instrument.
5. Build times: every intermediate `lake build` of the package completed
   in seconds (the semantics dependency replays); the fast gate is
   ~4-6 minutes (dominated by the root package). No pass approached the
   grind tripwire.
