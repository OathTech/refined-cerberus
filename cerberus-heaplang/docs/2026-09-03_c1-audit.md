## 3. Q3 — The `hκ` hypothesis: what it buys, what it costs

**The 22 statements that gained `ctl.κ = []` (DERIVED):**
`cerberusRound_classify`, `driveU_value_pure`, `drive_classifyU`,
`engine_adequacyU`, `engine_adequacyU_alloc`, `outcomesU_done`,
`project_triple`, `project_triple_alloc`, `project_triple_pure`,
`project_triple_pure_alloc`, `semantic_frameU`, `semantic_triple_soundU`,
`shipped_done`, `wp_load`, `wp_of_atomic`, `wp_store`, `wps_sound`,
`wps_sound_frame`, `wpt_drive_aux`, `wpt_engine_boundU`,
`wpt_engine_boundU_alloc`, `wpt_sound`.

**Is it a narrowing?** Formally a premise was added to public
statements; at the embedding it is `rfl`, so no previously provable
instance is lost — it is the old `SeqWF.stack` conjunct relocated to the
component that now carries the stack. Every consumer discharges it by
`rfl` (`procCtl_κ`, `spikeCtl_κ`; e.g. ProdEntry.lean:525
`(ctl := procCtl mainSym) rfl`).

**Is it forced?** Yes, by the Language instance, not by taste. Two
roots:
1. The VALUE ARM. `shipped_done`/`outcomesU_done` prove `[Step_done2 v]`
   via `step_ctx_done … (Ctl.toStack_of_κ_nil hκ)` — PROGRAM-DONE is
   selected by `Stack_empty` (engine col 1149: `match th_st.stack0 with |
   Stack_empty => … Step_done2 cval | Stack_cons2 … => … RETURN`). At
   `κ ≠ []` the engine's round IS the RETURN, which C1 does not mirror.
2. The RAW-WP LIFTING. `wp_of_atomic` (Rules.lean:210) does `obtain ⟨κ,
   pr, ℓ⟩ := ctl; subst hκ` and then needs `toVal ⟨e, ρ, ⟨[], pr, ℓ⟩, M⟩ =
   none` AND the successor `⟨ofVal w, ρ, ⟨[], pr, ℓ⟩, M⟩` to be a Language
   VALUE (`wp_lift_atomic_step`'s post is at a value). `toValRt` answers
   `none` at `κ ≠ []` (Step.lean:551), so at a non-empty stack the
   successor of an atomic step is NOT a value and the raw `WP … {{Φ}}`
   shape cannot be closed. Likewise `wps_sound`/`wpt_sound` rewrite with
   `toValRt_of_κ_nil … hκ` at the value case (Wps.lean:2727,
   Wpt.lean:2646).

**Does it mean the small axioms are only valid at an empty stack, i.e.
useless inside a callee after C2?** Precisely: the RAW-WP forms
(`wp_store`, `wp_load`, `wp_of_atomic`) and the COLLAPSES need `hκ`; the
JUDGMENT-LEVEL rules do not — `AtomicStep M ctl e ρ c P Q` (Rules.lean:194)
is stated at ANY `ctl` with successor `⟨ofVal w, ρ, ctl, M⟩`, and `grep
hκ Wps.lean Wpt.lean` finds ONLY `wps_sound`/`wps_sound_frame`/`wpt_sound`
— every `wps_*`/`wpt_*` rule (store, load, alloc, free, seq, run, …) is
control-general. So a store inside a procedure body at `κ ≠ []` HAS a
rule (`wps_store` at that `ctl`); what it lacks is a collapse to Iris WP
— which is exactly what C3's CPS `wps_sound` (design note Q1: `∀ (c :
Ctl) (Φ), ⌜c.proc = some f⌝ -∗ (∀ w ρ', Ψ w ρ' -∗ WP ⟨ofVal w, ρ', c, M⟩
{{Φ}}) -∗ WP ⟨e, ρ, c, M⟩ {{Φ}}`) supplies: the value premise is a WP at a
NON-value tuple that steps by `Step.ret`. The record's design decision 2
("`hκ` … so that C3's CPS collapse replaces it by the return clause
without restating the exports' shape") is therefore accurate and the
plan is recorded. The raw base stratum stays entry-only by design; its
only consumer is `Exhibit.lean:320` at `spikeCtl`.

**Cost to C2/C3 (my reading, for the brief):** C2 (call/return rules) —
`Step.ctl_eq` becomes a case analysis (the docstring says so); every
statement of the form `Step M (e, ρ, ctl, σ) (e', ρ', ctl, σ')` with the
SAME `ctl` on both sides (`engine_step_matchU`, `Frag.step`,
`Decomp.step_factor`, `loop_step_frag`, `driverDone_step`, `wpt_det_step`)
must become `ctl'`; `wps.pre`/`wpt.pre`'s step clause continues at the
SOURCE control (`F Ψ r.e r.ρ` under the fixed index `ctl`, Wps.lean
`wps.pre`; `wpt M ctl Ls k Ψ r.e r.ρ` in `wpt_step_eq`) — right at C1 by
`Step.retag`, but structurally "control-preserving"; C3's judgment
redesign must re-index the continuation at `r.ctl` or handle
call/return in dedicated clauses (N-3). None of this is a latent
unsoundness; it is the expected second half of "the configuration
grows".

### M-1 (Medium — coverage of the "one change"; not a soundness gap): the production lane's control is a phantom, not the driver thread's

**Location.** DriverCollapse.lean:1296 `loop_step_frag`; ProdLoop.lean:127
`driverDone_step`, :168 `wpt_driver_aux`, :276 `wpt_driver_done`, :344

**Claim (record §4, §1).** "the production plumbing (`loop_step_frag`,
`driverDone_step`, `wpt_driver_aux`, `wpt_driver_done*` — control
inferred from `hlb`)"; "`loop_step_frag`/`driverDone_step`/`wpt_driver_*`

"`loop_step_frag`'s conclusion shape is UNCHANGED (`update_thread_state 0
(M.thread e' ρ' c') …`)"; pre-registered criterion "`loop_step_frag`'s
shape survives C2".

**Tree's truth (verbatim, `loop_step_frag`).**
```
theorem loop_step_frag {M₀ : MachineCtx} {ctl : Ctl}
    (htd : M₀.tagDefs = fmapEmpty) (hex : M₀.extern = fmapEmpty)
    {Q : LabelMap} (hlb : M₀.labelsAt ctl.proc = Q)
    {p : sym} {th₀ : thread_state} (hproc : th₀.current_proc_opt = some p)
    …
    (hth : dst.core_state0.thread_states =
      [(0, (none, { th₀ with arena := e, env := ev0 :: evs }))])
    …
    (hQd : LabeledAt dst.core_run_state0 p Q)
    …

    … update_thread_state 0 { th₀ with arena := e', env := ρ' } dst.core_state0 …
```
`wpt_driver_done` adds `(hstack : th₀.stack0 = Stack_empty)`. There is
NO hypothesis relating `ctl` to `th₀`: not `ctl.proc = some p`, not
`th₀.stack0 = ctl.toStack`, not `th₀.exec_loc = ctl.execLoc`. The
conclusion is over `{ th₀ with arena, env }`, not `M₀.thread e' ρ' ctl`.

**Consequence.** Today: sound — the only control read of any C1 rule is
`Step.run`'s label lookup at `ctl.proc`, and `hlb` + `hQd` make the
mirror's map and the driver's map the same `Q` regardless of whether
`ctl.proc = some p`; no rule writes the control, so `th₀`'s control fields
riding unchanged is correct. But the brief's central question — "is the
live control mirrored from the ENGINE's thread fields, not invented" —
has a two-part answer: in the `Embeds`/`CerberusRound` lane, mirrored
(`M.thread … c.2.2.1`); in the PRODUCTION lane, the control is a free
parameter of the mirror that the driver thread never sees. C2's
`Step.call` writes `ctl` (design note: `⟨(c.proc, ctx) :: c.κ, some f,
push_exec_loc f M.currentLoc c.execLoc⟩`), and the engine writes
`th₀.stack0/current_proc_opt/exec_loc` — so `loop_step_frag`'s `ctl … ctl`
and `{ th₀ with arena, env }` CANNOT survive C2 as stated; the tie
(`th₀.stack0 = ctl.toStack ∧ th₀.current_proc_opt = ctl.proc ∧
th₀.exec_loc = ctl.execLoc`, or a restatement over `M₀.thread`) must be
added there, and `hproc`/`hstack` become derived. The design note's
pre-registered criterion is at risk and the record does not say so.

**Fix.** Either (a) land the tie now as three hypotheses (or state `hth`
over `M₀.thread e (ev0 :: evs) ctl` with `M₀.errno`/`currentLoc` matching
`prodThread`'s — `prodThread` is `stack0 := Stack_empty, exec_loc :=
ELoc_normal [(mainSym, other "Driver.drive")], current_proc_opt := some
mainSym`, i.e. the entry control is `⟨[], some mainSym, ELoc_normal [(mainSym,
…)]⟩`, NOT `procCtl mainSym`'s `default` execLoc — the tie will expose
that `procCtl` is a profile, not the production control), or (b) record
in DECISIONS/C2 brief that the production lane's `th₀`↔`ctl` tie is a C2
obligation and that `loop_step_frag`'s shape WILL change. (b) is enough
for the merge.
